# 🔎 New Standard — Minimum Font Size for Lesson Content

This adds a new rule to `AEF Lesson Standards.md` (the master file is read-only, so this is tracked separately — fold it in the next time the master file is edited directly).

---

## The rule

**No lesson content text may ever be smaller than the instruction font size.**

- Floor: **1.05rem** — the smaller of the two instruction variants (`.instruction` is 1.08rem, `.inst-light` is 1.05rem). Nothing a student reads or interacts with should go below 1.05rem, even elements that were previously documented with smaller "secondary" sizes.
- This **supersedes** the following rows in the existing "Font sizes" table (`AEF Lesson Standards.md`), which had sizes below the floor:

| Element | Old size | New size |
|---|---|---|
| Grammar table cells | `.95rem` | `1.05rem` |
| Listening answers (revealed) | `.92rem` italic | `1.05rem` italic |
| Speaking card example | `.88rem` italic | `1.05rem` italic |
| Vocab chips | `.95rem` | `1.05rem` |

Any other content element previously sized below 1.05rem (word-bank tiles, classify chips, circle/multiple-choice options, matching-pair items, placed answer tags, audio labels, glossary notes, book-placeholder notes, story-text placeholders, suggested-answer boxes) is also raised to the 1.05rem floor.

## What counts as "lesson content" (must meet the floor)

Anything the student reads as part of the lesson material or interacts with as part of an exercise: instructions, exercise sentences/questions, answer options and chips, table/reference text, story or reading text, notes/labels that convey lesson information, placed/typed answers.

## What's exempt (governed by their own already-fixed standards, not this rule)

- **Fixed navigation/UI chrome**: nav bar buttons, dots, slide counter, Notes button, notes toolbar buttons, notes textarea, Home button, Save Notes / Print Lesson buttons — these are app controls, not reading content, and several already have their own pinned sizes in other mandatory standard sections (e.g. the Homework button's `.95rem` is pinned by the Cover Slide standard).
- **Icon/number-only badges**: `.circ-num`, `.example-badge`, small emoji/checkmark glyphs (e.g. the 🔗 link icon on matched pairs) — single digits or icons, not prose.
- **Print-only CSS** (`@media print` block: page header, `.lesson-link-print`, `.slide-notes-print`) and the separate printable **Save Notes summary page** generated by `savePDF()` — these are export/print artifacts with their own already-documented fixed sizes in the Print Lesson standard section, not on-screen lesson content.
- **Cover / Homework Cover mandatory pinned elements** (title lines, homework badge, 🏠 all-courses link) — governed by the separate "MANDATORY STANDARD" sections that require copying exact values; don't alter those for this rule.

# 🔎 New Standard — No Placeholder Text in Student Answer Boxes

This adds a second new rule to `AEF Lesson Standards.md` (also tracked here since the master file is read-only).

## The rule

**Text boxes and text lines where a student is meant to write something must always be left completely empty — no placeholder text, ever.**

- No `placeholder="Type the correct sentence..."`, `placeholder="Complete the sentence..."`, `placeholder="Write your answer here..."`, or any other instructional/example filler inside an `<input>` or `<textarea>` a student types into.
- The instruction line above the exercise (`.instruction` / `.inst-light`) is where any guidance belongs — never inside the answer field itself.
- This applies to every exercise type that gives the student a blank to type in: sentence-rewrite boxes, listening-completion lines, writing-task textareas (50-word story, reading continuation, "make it personal" sentences), and any future typed-answer exercise.

## What's exempt

- **`#notesTA`** (the slide Notes panel) — this is app UI chrome for the tutor/student's own private notes, not lesson exercise content, and keeps its `data-placeholder="Your notes for this slide…"`.

## Applied to AEF4-3B on 2026-07-12

Removed all 16 `placeholder="..."` attributes from student-facing `.ans-input` elements across the file: the 7 sentence-rewrite boxes on the "Fix the adverb position" slide, the 6 listening-completion lines on the "Complete the sentence" slide, and the 3 writing-task textareas (50-word story, reading continuation, "make it personal"). `#notesTA`'s `data-placeholder` was left untouched as it's UI chrome, not lesson content. Verified with the standard JS syntax check + full jsdom exercise sweep.
